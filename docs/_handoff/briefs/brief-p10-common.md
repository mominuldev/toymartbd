## Machine
- PHP 8.4 on PATH (`php`). Node 26 on PATH works. `vendor/` and `node_modules/` are installed — do **not** run `composer install` / `npm install` unless you add a dependency (then say so).
- **Disk is ~6 GB free.** Never leave build output behind: delete any `.next`/`dist` dirs, `test-results/`, `playwright-report/`, screenshots you create. No storefront `next build` unless your brief says so.
- Temp files: your own folder under `$TMPDIR` (e.g. `$TMPDIR/p10-agent-N/`).
- The owner runs `php artisan serve` on :8000 and Vite on :5173 from this tree — never kill them, never delete `public/hot`, never `migrate:fresh` the default DB. Use your own SQLite file + port for anything you run (`DB_CONNECTION=sqlite DB_DATABASE=$TMPDIR/p10-agent-N/db.sqlite CACHE_STORE=file QUEUE_CONNECTION=sync SESSION_DRIVER=file SANCTUM_STATEFUL_DOMAINS=127.0.0.1:<port>`). `php artisan migrate --seed && php artisan db:seed --class=DemoDataSeeder` (read `database/seeders/Demo*`) gives realistic data for screenshots.
- Admin bundle build, if you need one (screenshots): `until mkdir $TMPDIR/admin-build.lock 2>/dev/null; do sleep 5; done; npm run build; rmdir $TMPDIR/admin-build.lock`. `public/hot` makes Laravel load the dev server instead — for your own `php artisan serve` instance point Vite at nothing by setting `VITE_HOT_FILE=$TMPDIR/p10-agent-N/hot` if supported, otherwise screenshot through the owner's Vite (it is running). Never `npm run dev`.

- **Report figures must reconcile with the ledger** (`financial_transactions` / `daily_financial_summaries` / `order_financials`). Revenue = recognised on delivery; cash = remittance (rule 10). Never conflate "orders placed value" with "revenue" — label each honestly. Bucket by **Dhaka date** (rule 11); Saturday–Friday report weeks (owner decision). Add a test that a seeded month of data matches the ledger to the poisha.
- Reads only: reporting code never writes to the ledger or stock. Heavy queries use indexes; check the query plan for anything over orders/order_items/financial_transactions and add an index migration only if needed (inside your N-block). Cache short-lived (≤5 min) with tags invalidated by the relevant domain events if you cache at all.
- **Never log or return a full phone number, email or address** to roles without `customers.view_pii` (rule 20) — follow how orders mask PII today.
- Permissions: reuse existing ones (`dashboard.view`, `reports.view`, `customers.view`, `customers.view_pii`, `finance.view`, `orders.view`, `purchasing.view`, `settings.view`, `settings.manage_integrations`) — read `RolesAndPermissionsSeeder` first.
