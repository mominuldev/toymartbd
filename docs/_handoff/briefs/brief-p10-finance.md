## Owner capital — domain decision (lead)
- New insert-only table `capital_entries`: `id` · `kind` (`contribution`|`drawing`) · `holder_id` → `capital_holders` · `amount` DECIMAL(14,2) Money cast (> 0) · `occurred_on` DATE (Dhaka) · `method` (reuse the expense payment-method enum: cash, bank, bKash, Nagad…) · `reference` NULL · `note` NULL · `reversal_of_id` NULL (self FK, UNIQUE — a reversal reverses one entry once) · `recorded_by` · timestamps. Model refuses update/delete. A mistake is fixed by a **reversing entry**, never an edit.
- `capital_holders`: `id` · `name` · `name_bn` NULL · `user_id` NULL (a staff account, optional) · `is_active` · timestamps. Owners and partners. No share percentages, no profit allocation (owner chose the plain option).
- Ledger (rule 8, 10): two new `LedgerEntryType` cases, additive: `owner_capital_in` (direction in) and `owner_drawing` (out); both `is_cash_movement = true`, `is_recognised_revenue = false` — they move cash and never touch the P&L. Written only via `Ledger::record` inside one Action per use case (`RecordCapitalEntry`, `ReverseCapitalEntry`); source `capital_entry` / `capital_reversal`. `daily_financial_summaries` gets one column per new type (expand-only migration) and the rollup includes them in cash in/out, not in recognised in/out. Invariant tests: P&L unchanged by capital entries; cash position changes by exactly the amount; finance:verify still green.
- API: `GET /finance/capital` (summary per holder: put in, taken out, net, last entry; totals; filters allowlisted: holder, kind, Dhaka date range), `GET /finance/capital/entries` (cursor list), `POST /finance/capital/entries` (FormRequest, `Idempotency-Key` required — it moves money), `POST /finance/capital/entries/{id}/reverse` (reason required), `GET/POST/PATCH /finance/capital/holders`. Permissions: read with `finance.view`; write with an existing finance-manage permission if one fits (read `RolesAndPermissionsSeeder`), else add `finance.manage_capital` (owner + finance manager defaults) — it reveals money, so it falls under rule 20a 2FA. Audit every write. 403 role tests (rule 21).
- Admin: Finance › Capital page + "New investment" (money in) / "Owner drawing" (money out) dialog + reverse flow; the Finance cash views (ledger, daily report / cash flow) show the new types with plain labels.
